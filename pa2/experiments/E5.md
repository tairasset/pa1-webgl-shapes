# E5 — Frame-rate independence (partially verified)

Student ID 242458. Baseline measured in the Codex in-app browser, with no
DevTools CPU throttling applied. Evidence: `timing-baseline.png` and
`E5-baseline-output.txt`. This is not the required Chrome/Firefox check.

## Prediction

Because t accumulates timestamp differences rather than a fixed step per
frame, one orbit should take 14 seconds, within the next rendered frame.
The 0.1-second clamp deliberately discards excess time from longer stalls.

## Result

| Baseline measurement | Observed value |
| --- | ---: |
| dt sample wall duration | 5.0000 s |
| Frame intervals sampled | 293 |
| Mean raw dt | 0.0170648464 s |
| Maximum raw dt | 0.0999000000 s |
| First frame reaching one orbit | 14.0167000000 s |
| Simulated time at that frame | 14.0167000000 s |
| Last frame interval | 0.0168000000 s |

The overshoot of 0.0167 s is smaller than the last frame interval. No interval
in the five-second baseline sample exceeded the clamp.

## Explanation

The first timestamp establishes the time origin and is excluded from the dt
sample. Subsequent raw timestamp differences are logged for five seconds.
The sample ends on the first frame reaching the five-second boundary; the
reported wall duration records any frame-boundary overshoot. The orbit check
ends on the first frame where simulated t reaches 14 seconds.

After removing the clamp, an animation-frame suspension can cause a large
dt on return, advancing the pose in one frame. With the clamp, each resumed
frame advances by at most 0.1 s. Background browsers may instead keep running
frames at a reduced rate, so the actual visibility test must establish which
behaviour occurred. No tab-return observation is claimed here.
